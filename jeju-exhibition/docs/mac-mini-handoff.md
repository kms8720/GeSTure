# 제주 전시 — Mac mini 실행·검수 안내

이 문서는 설치·실행·검수 방법을 정리한 참고 안내다. 변경 인수인계와 실제 검수 결과는 저장소 루트의 [HANDOFF.md](../../HANDOFF.md) 한 파일에 기록한다.

작성: 2026-10-29. 업데이트: 2026-11-11. 열린 감각 문장 개선은 [PR #26](https://github.com/kms8720/GeSTure/pull/26), 병합 커밋 `314d40c`에 포함되어 있다. 이 커밋에 고정하지 말고 이후 변경까지 포함한 최신 `main`을 받는다. 손 모델·전시 화면 통합 내용과 새 검증 기록은 루트 [HANDOFF](../../HANDOFF.md)를 함께 본다.

## 작업 범위와 시작점

- 사용자가 실행·테스트 장소를 **Mac mini**로 옮겼다. 이전 개발 Mac에서는 서버·시연·모델 테스트를 다시 켜지 않는다. 기존 전시 서버의 종료와 TCP 3002 리스너 없음은 확인했다.
- 저장소: https://github.com/kms8720/GeSTure
- 작업 기준 브랜치: `main`. 이번 문장 검수 대상은 PR #26 이후 최신 `main`이다. QR·워드클라우드 기반 PR #23도 이미 병합되어 있다.
- 이후 변경은 방향 확인 → 로컬 구현 → 브리핑 → GitHub 반영 여부 2차 승인 순서로 진행한다. 승인받은 뒤 커밋·푸시와 원격 `main` 반영까지 완료한다. 2026-11-08 지시가 이전 자동 반영 승인을 대체하며, 저장소 루트의 [AGENTS.md](../../AGENTS.md)를 따른다.
- 작업 디렉터리: 저장소 안의 `jeju-exhibition/`. Mac mini의 실제 체크아웃 경로를 확인한다. 이전 Mac의 절대 경로를 사용하지 않는다.
- 목표: 제주 전시의 휴대폰 조종 → 자모 후보 누적 → 단어 생성 → 단어 궤도 → 문장 모이기를 실제 장비에서 검증하고 보완한다.
- 미팅의 구현 결정·홍보 문구·장비 확인 사항은 [README의 미팅 반영 절](../README.md#2026-10-29-미팅-반영과-현장-준비)에 있다. 원본 녹음이나 전사본을 GitHub에 올리지 않는다.

## 인터넷 관객 참여 — 전시 시작 파일

현재 전시 운영은 GitHub Pages 고정 QR 입구와 Cloudflare Quick Tunnel을 사용한다. 관객은 같은 Wi-Fi에 접속할 필요가 없으며, 휴대폰과 Mac mini 각각 인터넷이 필요하다. 최초 도구 설치·모델 다운로드·GitHub 인증을 마친 후 저장소 루트 `전시 시작.command`를 더블 클릭한다. 준비 완료 후 손·단어·QR 화면이 열린다. 종료는 해당 터미널의 Control+C다.

4/6 단계는 새 공개 주소와 실시간 손 상태를 최대 3분 동안 재확인한다. 대기 중에는 15초 간격으로 DNS 조회·HTTP 응답·실시간 연결 오류를 표시한다. 창을 닫거나 시작 파일을 중복 실행하지 말고 6/6 완료 안내를 기다린다. 시간 초과 시 마지막 오류와 `data/exhibition-launcher/launcher.log`, `tunnel.log`를 확인한다. DNS 조회가 계속 실패하면 인터넷 연결을 확인하고 사전 검증한 네트워크로 전환한 뒤 재실행한다.

설치 명령, 현장 60분 점검, 오류 복구, 아직 실행하지 않은 검수는 루트 [HANDOFF의 전시 시작 안내](../../HANDOFF.md#2026-11-11-전시-시작-파일--무료-고정-qr-입구)에 모아 두었다. 고정 입구는 https://kms8720.github.io/GeSTure/ 이며, 손가락별 QR은 `?finger=thumb` 등 식별자를 사용한다. 임시 터널 주소를 직접 인쇄하지 않는다. 프로그램의 준비 완료 확인과 휴대폰 데이터 조종 검수 후 인쇄한다.

아래 수동 서버·LAN 설정은 내부 검수나 LAN 방식 운영을 위한 절차다. 인터넷 시작 파일과 수동 서버를 동시에 실행하지 않는다. 시작 파일은 `.env`를 수정하지 않고 `CONNECTION_MODE=internet`, 현재 `PUBLIC_ORIGIN`, 고정 `JOIN_ENTRY_URL`을 실행 프로세스에 전달한다. 이 경우 Wi-Fi 정보와 고정 LAN IP 설정은 관객 참여에 필요하지 않다.

## Mac mini에서만 실행할 준비 절차

1. 먼저 현지 변경을 확인하고 보존한다. 로컬과 원격 커밋이 다르면 동기화·실행 전에 루트 `HANDOFF.md`의 로컬 버전과 원격 최신 버전을 확인한다. 아래 두 읽기 명령은 같은 파일의 버전을 조회하며 별도 인수인계 문서를 만들지 않는다.

```sh
# GeSTure 저장소 루트에서
git status --short --branch
git fetch origin
git rev-parse HEAD origin/main
git log --oneline --left-right HEAD...origin/main
cat HANDOFF.md
git show origin/main:HANDOFF.md
```

미커밋 변경이나 로컬만의 커밋이 있으면 먼저 보존하고 내용을 확인한다. 단순히 뒤처졌고 작업 트리가 정리된 경우에는 아래처럼 갱신한다. 분기되었다면 원인을 확인해 기존 작업을 유지하면서 통합하며, `reset --hard`나 강제 푸시로 맞추지 않는다.

```sh
git switch main
git pull --ff-only origin main
git rev-parse HEAD
git merge-base --is-ancestor 314d40c HEAD
cat AGENTS.md
cat HANDOFF.md
```

`merge-base`의 종료 코드가 0이면 문장 개선 커밋을 포함한다. 최신 HANDOFF가 추가 안내하는 문서도 읽고, 이때의 전체 커밋 SHA를 테스트 결과에 남긴다.

2. Node.js 22.18 이상과 Ollama가 필요하다. 서버가 기대하는 모델은 `qwen2.5:7b-instruct`이며 Ollama 기본 주소는 `http://127.0.0.1:11434`다. `ollama list`로 모델을 확인하고 없을 때만 `ollama pull qwen2.5:7b-instruct`로 받는다. 이미 실행 중인 Ollama 서버를 중복 실행하지 않는다.
3. 의존성·로컬 환경 파일을 준비한다. 잠금 파일이 있으므로 `npm ci`를 사용한다.

```sh
cd jeju-exhibition
npm ci
npm run setup
```

4. `.env`를 Mac mini 환경에 맞게 편집한다.

| 항목 | 설정과 주의점 |
| --- | --- |
| `PORT` | `3002` |
| `PUBLIC_ORIGIN` | `http://<Mac mini의 LAN IP>:3002`. 이전 Mac의 IP·localhost·Vite 주소를 관객 QR에 사용하지 않는다. |
| `WIFI_SSID`, `WIFI_PASSWORD` | 실제 관객용 Wi-Fi 정보. 아직 현장 정보는 확정되지 않았다. |
| `OPERATOR_TOKEN` | setup이 로컬에 생성한다. 기존 값이 있으면 보존한다. 채팅·로그·QR·Git에 출력하지 않는다. |
| `EXHIBITION_STRICT` | `1` 유지. 단어 출력은 전시 단어장으로 제한한다. |
| `OLLAMA_MODEL`, `OLLAMA_URL` | `qwen2.5:7b-instruct`, `http://127.0.0.1:11434` |
| `WORD_DEADLINE_MS` | `20000` |
| `SENTENCE_DEADLINE_MS` | `18000`. 작성·검토를 합친 전체 상한이다. |
| `OLLAMA_KEEP_ALIVE` | `8h`. 상주 메모리 사용량과 실제 장비 성능을 확인한다. |
| `WORD_CLOUD_FILE` | 기본 `data/word-cloud.json`. 별도 QA 서버는 반드시 다른 기록 경로를 사용한다. |

**아래 수동 LAN 방식으로 운영할 때만** 관객 휴대폰과 Mac mini는 서로 통신할 수 있는 LAN에 있어야 한다. Mac mini 유선·휴대폰 무선도 같은 LAN이면 가능하다. 게스트 Wi-Fi의 기기 간 통신 차단, 방화벽, DHCP 주소 예약은 현장에서 확인한다. 네트워크를 바꾸면 참여 origin과 QR도 갱신한다. [네트워크 안내](network-setup.md)를 따른다.

5. Mac mini에서 검사·빌드 후 서버를 실행한다. 이 명령들을 이전 개발 Mac에서 대신 실행하지 않는다.

```sh
npm run typecheck
npm test
npm run build
npm start
```

6. 서버 예열 완료를 확인하고 다른 터미널에서 실제 LAN 주소로 점검한다. 아래 자리표시자는 Mac mini IP로 바꾼다.

```sh
npm run check:network -- http://<MAC_MINI_IP>:3002
```

이는 실행한 컴퓨터에서의 HTTP·소켓·주소 설정 검사다. 휴대폰에서의 접속 성공을 대신하지 않는다.

| 화면 | 경로 | 용도 |
| --- | --- | --- |
| 모아보기 | `/exhibition` | 손·최근 단어·클라우드·조종기를 한 화면에서 확인 |
| 손 | `/display/hand` | 세로 디스플레이, 기본은 손만 표시 |
| 단어 구름 | `/display/word` | 별도 큰 화면, 궤도와 문장 연출 |
| 최근 단어 | `/display/latest-word` | 새 단어와 여섯 손 모양 진행 |
| 별도 클라우드 | `/word-cloud/` | 같은 서버 기록의 추가 전시 디자인 |
| 관객 QR | `/join/qr` | 손가락별 QR 5개 |
| 운영 | `/monitor` | 운영자 키로 인증, 자모·입력·결과·문장 관리 |
| 디버그 | `/display/hand?debug=1` | D 키로 표시/숨김 |
| 연결 확인 | `/check` | 휴대폰에서 열어 확인 |

모아보기의 조종기 다섯 개는 실제 손가락 자리를 사용한다. 휴대폰 QR 실기 전 각 미리보기의 `조종 자리 비우기`로 반환하거나, 모아보기 탭을 닫고 15초 재접속 유예가 끝난 뒤 참여한다.

## GitHub로 함께 이동하지 않는 것

- `.env`, 운영자 키, Wi-Fi 설정: Mac mini에서 새로 설정한다.
- `node_modules`, 빌드 결과, Ollama 실행 환경과 모델 가중치: Mac mini에서 준비한다.
- `data/word-cloud.json`과 백업: Git 제외다. 새 설치는 단어가 없는 것이 정상이다. 기존 화면의 단어가 저절로 복원될 것으로 기대하지 않는다.
- 기존 기록을 이어야 하면 양쪽 서버를 멈춘 상태에서 별도 파일 전송한다. Mac mini에 기록이 있으면 먼저 백업하고 덮어쓰지 않는다. 전송 후 파일 권한·`WORD_CLOUD_FILE` 경로를 확인한다. 이번 이관에서는 기록 파일을 GitHub에 올리거나 Mac mini로 전송하지 않았다.
- 녹음·자동 전사·검증 스크린샷은 각각 검증한 개발 장비의 로컬에만 있다. 코드 실행의 필수 파일이 아니며 이번 인수인계의 결정 사항은 문서에 정리돼 있다.
- 손가락 위치는 관객 연결 종료·자리 이동 때 유지하지만, 서버 프로세스 재시작 후 영속 복원하는 기능은 없다.

## 유지해야 할 최신 동작

- 휴대폰은 손가락 이름과 세로 드래그 조종기 하나만 표시한다. 위로 밀면 펴지고 아래로 내리면 접힌다.
- 엄지·검지·중지·약지·소지 QR은 지정 손가락으로 연결한다. 사용 중이면 그 손가락을 기다린다. 같은 폰으로 다른 QR을 스캔하면 조종 권한을 옮기되 이전 손가락의 굽힘을 유지한다.
- 연결 복구 유예는 15초다. 마지막 자세가 자동으로 새 입력이 되지 않도록 단어 완료·초기화·자리 반환 후에는 다음 실제 조작까지 인식을 멈춘다.
- 17개 자세 클래스, 400ms 유지 확정, 100ms 인식 틱. 6개 입력 슬롯이 차면 단어를 생성한다. 손목 방향 때문에 한 자세에 여러 자모 후보가 있을 수 있다.
- 새 단어 직후에는 **그 단어 + 전체 기록에서 무작위로 뽑은 다른 단어**를 쓴다. 반복 입력도 동일하다. 모델이 의미상 잘 어울리는 두 단어를 고르도록 되돌리지 않는다.
- 입력이 없어도 서버 한 곳에서 자동 생성한다. 가능한 두 단어 조합을 무작위 순서로 순회하고, 생성 완료 후 10초 대기한다. 화면은 약 15초 주기로 전환하며, 문장을 약 7초 표시한다.
- 제주 장애예술페스타 열린 감각의 문장 방향은 **함께 표현하는 구체적 장면에 여운을 남기기**다. 서로 다른 감각·몸짓·표현·속도의 동등한 참여를 담는다. 장면에서 이해 가능한 비유는 허용하며 뜬금없는 의인화·인과, 장애에 대한 동정·결핍·극복이나 반복 구호는 거부한다.
- 후보 작성 → 서버의 형식·두 단어·본문의 행동 인용 검사 → 같은 로컬 모델에 별도 호출하여 문법·장면/인과·단어 활용·주제 연결·동등한 참여를 검토한다. 다섯 판정이 모두 true이고 `themeEvidence`가 선택한 본문의 실제 구절이어야 통과한다. 별도 검토가 별개의 모델이나 품질 보장을 뜻하지는 않는다.
- 새 결과는 다음 문장 모이기 연출에서 우선 표시한다. 자동 생성 실패는 기존 문장을 유지하고 다음 조합을 시도한다. 새 입력·수동 생성 실패는 같은 두 단어를 저마다의 방식으로 표현하여 함께 장면을 만드는 기본 문장을 사용한다. 단어 생성이 문장 생성을 우선한다.
- 최근 고유 단어 50개·문장 80개를 저장한다. 이전 주제 문장은 `.before-jeju-open-senses-v2`로 백업하고 단어·최신 입력은 유지한다. 실제 기록에 예시 단어를 심지 않는다.
- 모든 POST 운영 API는 운영자 인증이 필요하다. 인증 우회로 테스트를 편하게 만들지 않는다.

## 다음 테스트 우선순위

2026-11-08 문장 수정은 이전 Mac에서 코드 검토만 수행했다. 타입 검사·자동 테스트·빌드와 실제 Ollama 문장 품질·18초 이내 처리 여부는 Mac mini에서 확인해야 한다. 기존 테스트 통과 기록은 이 수정의 통과 기록이 아니다.

- `npm run typecheck`, `npm test`, `npm run build`를 실행한다. 전체 테스트에는 문장 회귀 검사가 포함되며, 실패 원인을 좁힐 때 `npm run test:word-cloud`를 따로 쓸 수 있다. 문장 테스트는 모의 응답의 형식·판정·근거 처리와 저장 전환을 검증하며 실제 모델의 문학적 품질을 판정하지 않는다.
- 테스트 전 관객 기록을 별도 보관하고 별도의 `WORD_CLOUD_FILE`로 검수한다. 이전 주제 기록을 읽었을 때 단어·최신 입력이 유지되고 옛 문장이 재생되지 않으며 `.before-jeju-open-senses-v2` 백업이 보존되는지 확인한다.
- 실제로 모인 여러 조합에서 새 단어 포함, 무작위 상대 단어, 공동 표현의 의미, 이해 가능한 여운, 동정·극복 서사 부재를 검토한다. 성공·검토 탈락·시간 초과를 구분해서 생성 지연도 기록한다.
- 모델 실패 시 최신 두 단어의 기본 문장이 `/display/word`와 `/word-cloud/` 모두에 표시되고 `우리`·`함께`처럼 연결 문구에도 있는 단어의 궤도·문장 위치가 재시작 후 유지되는지 확인한다.

문장 품질은 아직 해결 완료가 아니다. 이전 Mac에서 `함께 만든 말이 평화로운 하늘에 반사되었다` 같은 어색한 비유가 검토를 통과한 사례가 있었다. 해당 시험 문장은 백업 후 내려 두었고 검토 지시를 보강했다. 주제 연결이 약하거나 한국어가 부자연스러운 문장이 여전히 나올 수 있다. 긴 지시에서는 18초 제한으로 연속 생성이 실패해 지시와 장면 계획을 줄였다. **새 문장이 잘 안 바뀌면 먼저 모델 지연·검토 탈락·서버의 실제 추가 여부(`sentenceRevision`)를 분리해서 조사한다.** 단순히 문장 연출 타이머를 줄여 해결된 것으로 판단하지 않는다.

## 열린 감각 문장 생성·품질 검수 순서

이번 검수의 목표는 **여운이 있으면서 장애예술과 함께 참여하는 의미가 읽히고, 뜬금없는 연결이 없는 문장**이다. 행사명을 넣었는지보다 서로 다른 감각·표현·속도가 동등하게 참여하는 장면이 읽히는지 판단한다. 모의 모델을 쓰는 자동 테스트 통과를 실제 문장 품질 검증으로 대신하지 않는다.

### 1. 자동 검사와 준비

위 준비 절차에 따라 Node 22.18 이상·의존성·기존 `.env`·Ollama 모델을 확인한다. `jeju-exhibition/`에서 다음을 실행한다. 오류가 있으면 오류와 실행 커밋을 기록하고 원인을 확인한다.

```sh
npm run typecheck
npm test
npm run build
```

운영 관객 기록은 보존하고, 기능 검수는 별도의 기록으로 진행한다. 다음 명령은 **3번 앱 검수 단계에서** 기존 서버와 포트가 겹치지 않게 실행 상태를 확인한 뒤 사용한다. 이 환경 변수는 해당 프로세스에만 적용하며 `.env`의 운영 기록 경로는 바꾸지 않는다.

```sh
WORD_CLOUD_FILE=data/qa-open-senses-20261108.json npm start
```

별도 품질 측정과 앱의 자동 생성이 같은 Ollama에 동시에 요청하지 않도록 **품질 측정 → 앱 검수**를 순서대로 진행한다. 서버를 중복 기동하거나 이미 실행 중인 Ollama를 새로 띄우지 않는다.

### 2. 실제 모델의 문장 품질

AI 세션은 `server/environment.ts`를 먼저 import해 `.env` 설정을 적용한 뒤, `server/sentenceComposition.ts`의 실제 `generateCloudSentence`를 호출하는 임시 실행 코드를 `data/` 아래에서 사용할 수 있다. 운영 데이터를 수정하거나 가짜 문장을 전시 기록에 넣지 않는다. 실제 `OLLAMA_MODEL`과 기본 18초 제한을 유지하고, 첫 호출의 예열 지연은 이후 호출과 구분한다.

- **10개 서로 다른 조합을 각 2회, 총 20회** 순차 생성한다. 단어는 `server/vocabulary.ts`의 실제 전시 단어장에서 고르고, 같은 쌍의 두 번째 요청에는 첫 채택 문장을 `avoidSentences`로 전달한다.
- 회귀 확인 조합에는 `새벽–대답`, `평화–대답`, `달–바다`, `우리–함께`를 포함하고, 나머지는 단어장에서 무작위로 정한다. 이 고정 조합은 품질 검수 입력일 뿐 전시의 무작위 추첨 규칙을 바꾸는 것이 아니다.
- 각 호출마다 **두 단어 / 채택된 실제 문장 또는 미채택 / 소요 ms / 오류 유형 / 사람이 읽고 판단한 문제점**을 기록한다. `null`은 후보 형식·의미 검토 등을 통과하지 못한 결과이며 세부 이유가 관찰되지 않았다면 추정해서 적지 않는다. 시간 초과·요청 실패·응답 파싱 오류는 별도로 기록한다.
- API의 5개 판정이 모두 true여도 결과를 직접 읽는다. 문법과 단어 관계가 자연스러운지, 공동 표현·참여의 의미가 본문에서 읽히는지, 비유를 이해할 수 있는지, 장애에 대한 동정·극복·일방적 시혜가 없는지 확인한다.
- 같은 문장 구조와 “함께 … 만들었다”만 반복하는지도 기록한다. 좋은 예문 몇 개만 골라 성공으로 보고하지 말고, 생성된 모든 결과와 실패 횟수를 함께 남긴다. 검토 탈락이 많아 기본 문장만 보이는 경우도 품질 문제로 분리한다.

결과는 `data/open-senses-quality-20261108/` 같은 Git 제외 폴더에 보관한다. 보고에는 총 시도·채택·미채택·오류 횟수와 성공 호출의 평균·최대 시간, 실제 좋은 문장과 어색한 문장·이유를 포함한다. 예시 문장을 손으로 고쳐 쓴 뒤 모델 출력으로 보고하지 않는다.

### 3. 실제 앱과 화면

- `/monitor`, `/display/word`, `/word-cloud/`를 연다. 실제 조작으로 서로 다른 단어 두 개 이상을 만들고 새 단어 → 구름 → 문장으로 모이기까지 확인한다. 휴대폰이 하나라면 `npm run demo:word`로 보조할 수 있지만 같은 단어가 반복되면 서로 다른 단어가 생겼다고 판단하지 않는다.
- 새 입력은 **그 단어 + 무작위 상대 단어**를 포함하고, 반복 입력도 같은 규칙으로 새로 구성되는지 본다. 운영 화면의 `문장 다시 구성`은 전체에서 두 단어를 뽑아야 한다.
- 입력 없이도 자동으로 새 조합을 시도하고 다음 연출에서 새 문장이 우선 표시되는지 확인한다. `/word-cloud` JSON의 `sentenceRevision`과 실제 본문 변화를 함께 확인한다. 화면은 약 15초 주기로 전환하며 문장을 약 7초 표시한다. 새 문장의 생성 간격은 모델 처리 시간에 따라 달라진다.
- `/monitor`에서 `AI 작성·검토`와 `기본 연결 문장`을 구분한다. 모델 실패·검토 탈락 시에도 최신 두 단어를 유지하는지, 두 클라우드 화면이 같은 결과를 보여 주는지 본다. 자동 생성 실패는 기존 문장을 유지하는 것이 정상이다.
- 기존 주제 기록의 **복사본**으로 전환을 확인한다. `.before-jeju-open-senses-v2` 백업, 단어·최신 입력 보존, 옛 문장의 재생 제외, 재시작 복원을 검사한다. 운영 원본은 덮어쓰지 않는다.

### 4. 결과 전달과 수정

테스트한 커밋·장비·모델, 자동 검사 결과, 20회 품질 기록 요약, 실제 문장 예시, 화면 확인 결과와 남은 문제를 사용자에게 브리핑한다. 실행·검수 결과는 루트 HANDOFF에 남긴다. 수정이 필요하면 먼저 개선 방향을 확인받고 로컬에서 수정한 뒤, GitHub 반영은 별도의 2차 승인을 받는다. 테스트 요청만으로 프롬프트 변경이나 `main` 자동 반영을 승인받은 것으로 보지 않는다.

휴대폰이 한 대뿐이면 `npm run demo:word`로 실제 인식 경로의 시연을 보조할 수 있다. 운영자 API로 손 모양을 입력하므로 실행 중에는 관객 조작을 멈추며, 종료 시 손을 편다. 이는 다중 실기 테스트를 대신하지 않는다. 첫 단어가 나온 뒤 두 번째 고유 단어가 생겨야 문장 연출을 확인할 수 있다.

## 이미 확인한 것과 아직 확인하지 못한 것

- 기능 변경 과정에서 전체 자동 테스트 66개가 통과했다. 이후 행동 활용형 회귀 검사 1개를 추가했고 최종 문장 구성 대상 9개·타입 검사 통과, 클라이언트 빌드 통과를 확인했다. 최종 전체 스위트는 Mac mini에서 다시 실행한다.
- 이전 Mac의 브라우저에서 QR 배정·드래그·입력 디버그·자모→단어·문장 모이기·세로 540×960 손 화면을 확인했다. 사용자도 iPhone 엄지 움직임을 확인했다.
- Mac mini에서 실행해 본 결과는 아직 없다. 그 장비의 모델 속도·메모리 여유·두 모니터 출력·실기 접속 성공을 추정하지 않는다.
- 현장 SSID·DHCP 예약, 실제 iPhone·Android 다중 접속, 두 디스플레이와 8시간 리허설, 인터넷 차단·인쇄 QR 검증이 남아 있다. 이 확인 전에는 전시 준비 완료로 선언하거나 관련 이슈를 닫지 않는다.
