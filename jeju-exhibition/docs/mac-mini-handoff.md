# 제주 전시 — Mac mini AI 세션 인수인계

작성: 2026-10-29. 기능 기준 커밋: `58dc1fb`.

## 작업 범위와 시작점

- 사용자가 실행·테스트 장소를 **Mac mini**로 옮겼다. 이전 개발 Mac에서는 서버·시연·모델 테스트를 다시 켜지 않는다. 기존 전시 서버의 종료와 TCP 3002 리스너 없음은 확인했다.
- 저장소: https://github.com/kms8720/GeSTure
- 브랜치: `feat/mobile-qr-controllers`. PR: https://github.com/kms8720/GeSTure/pull/23 (열림, 미병합).
- 작업 디렉터리: 저장소 안의 `jeju-exhibition/`. Mac mini의 실제 체크아웃 경로를 확인한다. 이전 Mac의 절대 경로를 사용하지 않는다.
- 목표: 제주 전시의 휴대폰 조종 → 자모 후보 누적 → 단어 생성 → 단어 궤도 → 문장 모이기를 실제 장비에서 검증하고 보완한다.
- ACC의 `virtual-hand-rigged-final/`과 홀로그램 후속 기획은 이번 구현 범위 밖이다.
- 미팅의 구현 결정·홍보 문구·장비 확인 사항은 [README의 미팅 반영 절](../README.md#2026-10-29-미팅-반영과-현장-준비)에 있다. 원본 녹음이나 전사본을 GitHub에 올리지 않는다.

## Mac mini에서만 실행할 준비 절차

1. 먼저 `git status --short`로 현지 변경을 확인하고 보존한다. 기능 기준 커밋만 고정해서 받지 말고 인수인계 문서가 포함된 브랜치 최신 상태를 받는다.

```sh
# GeSTure 저장소 루트에서, 기존 변경을 확인한 뒤
git fetch origin
git switch feat/mobile-qr-controllers
git pull --ff-only origin feat/mobile-qr-controllers
git log -3 --oneline
```

2. Node.js 22.18 이상과 Ollama가 필요하다. 서버가 기대하는 모델은 `qwen2.5:7b-instruct`이며 Ollama 기본 주소는 `http://127.0.0.1:11434`다. `ollama list`로 모델을 확인하고 없을 때만 `ollama pull qwen2.5:7b-instruct`로 받는다. 이미 실행 중인 Ollama 서버를 중복 실행하지 않는다.
3. 의존성·로컬 환경 파일을 준비한다. 잠금 파일이 있으므로 `npm ci`를 사용한다.

```sh
cd jeju-exhibition
npm ci
npm run setup
```

4. `.env`를 Mac mini 환경에 맞게 편집한다.

| 항목 | 설정과 주의점 |
| --- | --- |
| `PORT` | `3002` |
| `PUBLIC_ORIGIN` | `http://<Mac mini의 LAN IP>:3002`. 이전 Mac의 IP·localhost·Vite 주소를 관객 QR에 사용하지 않는다. |
| `WIFI_SSID`, `WIFI_PASSWORD` | 실제 관객용 Wi-Fi 정보. 아직 현장 정보는 확정되지 않았다. |
| `OPERATOR_TOKEN` | setup이 로컬에 생성한다. 기존 값이 있으면 보존한다. 채팅·로그·QR·Git에 출력하지 않는다. |
| `EXHIBITION_STRICT` | `1` 유지. 단어 출력은 전시 단어장으로 제한한다. |
| `OLLAMA_MODEL`, `OLLAMA_URL` | `qwen2.5:7b-instruct`, `http://127.0.0.1:11434` |
| `WORD_DEADLINE_MS` | `20000` |
| `SENTENCE_DEADLINE_MS` | `18000`. 작성·검토를 합친 전체 상한이다. |
| `OLLAMA_KEEP_ALIVE` | `8h`. 상주 메모리 사용량과 실제 장비 성능을 확인한다. |
| `WORD_CLOUD_FILE` | 기본 `data/word-cloud.json`. 별도 QA 서버는 반드시 다른 기록 경로를 사용한다. |

관객 휴대폰과 Mac mini는 서로 통신할 수 있는 LAN에 있어야 한다. Mac mini 유선·휴대폰 무선도 같은 LAN이면 가능하다. 게스트 Wi-Fi의 기기 간 통신 차단, 방화벽, DHCP 주소 예약은 현장에서 확인한다. 네트워크를 바꾸면 참여 origin과 QR도 갱신한다. [네트워크 안내](network-setup.md)를 따른다.

5. Mac mini에서 검사·빌드 후 서버를 실행한다. 이 명령들을 이전 개발 Mac에서 대신 실행하지 않는다.

```sh
npm run typecheck
npm test
npm run build
npm start
```

6. 서버 예열 완료를 확인하고 다른 터미널에서 실제 LAN 주소로 점검한다. 아래 자리표시자는 Mac mini IP로 바꾼다.

```sh
npm run check:network -- http://<MAC_MINI_IP>:3002
```

이는 실행한 컴퓨터에서의 HTTP·소켓·주소 설정 검사다. 휴대폰에서의 접속 성공을 대신하지 않는다.

| 화면 | 경로 | 용도 |
| --- | --- | --- |
| 손 | `/display/hand` | 세로 디스플레이, 기본은 손만 표시 |
| 단어 | `/display/word` | 별도 큰 화면, 궤도와 문장 연출 |
| 관객 QR | `/join/qr` | 손가락별 QR 5개 |
| 운영 | `/monitor` | 운영자 키로 인증, 자모·입력·결과·문장 관리 |
| 디버그 | `/display/hand?debug=1` | D 키로 표시/숨김 |
| 연결 확인 | `/check` | 휴대폰에서 열어 확인 |

## GitHub로 함께 이동하지 않는 것

- `.env`, 운영자 키, Wi-Fi 설정: Mac mini에서 새로 설정한다.
- `node_modules`, 빌드 결과, Ollama 실행 환경과 모델 가중치: Mac mini에서 준비한다.
- `data/word-cloud.json`과 백업: Git 제외다. 새 설치는 단어가 없는 것이 정상이다. 기존 화면의 단어가 저절로 복원될 것으로 기대하지 않는다.
- 기존 기록을 이어야 하면 양쪽 서버를 멈춘 상태에서 별도 파일 전송한다. Mac mini에 기록이 있으면 먼저 백업하고 덮어쓰지 않는다. 전송 후 파일 권한·`WORD_CLOUD_FILE` 경로를 확인한다. 이번 이관에서는 기록 파일을 GitHub에 올리거나 Mac mini로 전송하지 않았다.
- 녹음·자동 전사·검증 스크린샷은 이전 Mac 로컬에만 있다. 코드 실행의 필수 파일이 아니며 이번 인수인계의 결정 사항은 문서에 정리돼 있다.
- 손가락 위치는 관객 연결 종료·자리 이동 때 유지하지만, 서버 프로세스 재시작 후 영속 복원하는 기능은 없다.

## 유지해야 할 최신 동작

- 휴대폰은 손가락 이름과 세로 드래그 조종기 하나만 표시한다. 위로 밀면 펴지고 아래로 내리면 접힌다.
- 엄지·검지·중지·약지·소지 QR은 지정 손가락으로 연결한다. 사용 중이면 그 손가락을 기다린다. 같은 폰으로 다른 QR을 스캔하면 조종 권한을 옮기되 이전 손가락의 굽힘을 유지한다.
- 연결 복구 유예는 15초다. 마지막 자세가 자동으로 새 입력이 되지 않도록 단어 완료·초기화·자리 반환 후에는 다음 실제 조작까지 인식을 멈춘다.
- 17개 자세 클래스, 400ms 유지 확정, 100ms 인식 틱. 6개 입력 슬롯이 차면 단어를 생성한다. 손목 방향 때문에 한 자세에 여러 자모 후보가 있을 수 있다.
- 새 단어 직후에는 **그 단어 + 전체 기록에서 무작위로 뽑은 다른 단어**를 쓴다. 반복 입력도 동일하다. 모델이 의미상 잘 어울리는 두 단어를 고르도록 되돌리지 않는다.
- 입력이 없어도 서버 한 곳에서 자동 생성한다. 가능한 두 단어 조합을 무작위 순서로 순회하고, 생성 완료 후 10초 대기한다. 화면의 약 10초 연출 주기와 새 문장 생성 간격은 다르다.
- 문장 주제는 **서로 다른 움직임, 함께 만드는 말**이다. 서로의 표현을 듣기·속도 기다리기·함께 참여하기를 구체적 장면으로 표현한다. 장애에 대한 동정·결핍·극복이나 반복 구호를 목표로 하지 않는다.
- 후보 작성 → 서버의 형식·단어 검사 → 같은 로컬 모델에 별도 호출하여 문법·장면/인과·단어 활용·주제 연결 검토를 수행한다. 네 판정이 모두 true여야 통과한다. 별도 검토가 별개의 모델이나 품질 보장을 뜻하지는 않는다.
- 새 결과는 다음 문장 모이기 연출에서 우선 표시한다. 자동 생성 실패는 기존 문장을 유지하고 다음 조합을 시도한다. 새 입력·수동 생성 실패는 같은 두 단어의 중립 문장을 사용한다. 단어 생성이 문장 생성을 우선한다.
- 최근 고유 단어 50개·문장 80개를 저장한다. 이전 주제 미검토 문장은 `.before-barrier-free-coexistence-v1`로 백업하고 단어는 유지한다. 실제 기록에 예시 단어를 심지 않는다.
- 모든 POST 운영 API는 운영자 인증이 필요하다. 인증 우회로 테스트를 편하게 만들지 않는다.

## 다음 테스트 우선순위

| 우선순위 | 확인할 일 | 확인 기준 |
| --- | --- | --- |
| P0 | Mac mini 초기 실행·LAN·모델 예열 | 새 IP로 QR 5개가 생성되고 실제 iPhone·Android에서 지정 손가락을 조종한다. |
| P0 | 단어→문장 전체 흐름 | 실제 자세 입력으로 서로 다른 단어를 2개 이상 만든다. 최신 입력 포함·무작위 상대 단어·새 결과 우선 표시를 확인한다. |
| P0 | 문장 품질·생성 지연 | 여러 조합에서 수 분 이상 관찰하고 성공·검토 탈락·시간 초과와 소요 시간을 구분한다. 단어 선택 규칙을 유지하면서 개선한다. |
| P0 | 두 실제 디스플레이 | 손 세로·단어 별도 화면을 동시에 연결해 잘림·문장 가독성·애니메이션·발열과 프레임 저하를 확인한다. |
| P1 | 참여자 교체·복구 | 5명 조종+3명 대기, 다른 QR 이동, 15초 이상 끊김, 재접속 후 독점·승계·자세 유지·중복 입력 방지를 확인한다. |
| P1 | 종료·재시작·장시간 운전 | 기록 복원, 인터넷 차단 상태의 로컬 운영, 고정 IP/인쇄 QR, 실제 장비 8시간 리허설을 수행한다. |

문장 품질은 아직 해결 완료가 아니다. 이전 Mac에서 `함께 만든 말이 평화로운 하늘에 반사되었다` 같은 어색한 비유가 검토를 통과한 사례가 있었다. 해당 시험 문장은 백업 후 내려 두었고 검토 지시를 보강했다. 주제 연결이 약하거나 한국어가 부자연스러운 문장이 여전히 나올 수 있다. 긴 지시에서는 18초 제한으로 연속 생성이 실패해 지시와 장면 계획을 줄였다. **새 문장이 잘 안 바뀌면 먼저 모델 지연·검토 탈락·서버의 실제 추가 여부(`sentenceRevision`)를 분리해서 조사한다.** 단순히 문장 연출 타이머를 줄여 해결된 것으로 판단하지 않는다.

휴대폰이 한 대뿐이면 `npm run demo:word`로 실제 인식 경로의 시연을 보조할 수 있다. 운영자 API로 손 모양을 입력하므로 실행 중에는 관객 조작을 멈추며, 종료 시 손을 편다. 이는 다중 실기 테스트를 대신하지 않는다. 첫 단어가 나온 뒤 두 번째 고유 단어가 생겨야 문장 연출을 확인할 수 있다.

## 이미 확인한 것과 아직 확인하지 못한 것

- 기능 변경 과정에서 전체 자동 테스트 66개가 통과했다. 이후 행동 활용형 회귀 검사 1개를 추가했고 최종 문장 구성 대상 9개·타입 검사 통과, 클라이언트 빌드 통과를 확인했다. 최종 전체 스위트는 Mac mini에서 다시 실행한다.
- 이전 Mac의 브라우저에서 QR 배정·드래그·입력 디버그·자모→단어·문장 모이기·세로 540×960 손 화면을 확인했다. 사용자도 iPhone 엄지 움직임을 확인했다.
- Mac mini에서 실행해 본 결과는 아직 없다. 그 장비의 모델 속도·메모리 여유·두 모니터 출력·실기 접속 성공을 추정하지 않는다.
- 현장 SSID·DHCP 예약, 실제 iPhone·Android 다중 접속, 두 디스플레이와 8시간 리허설, 인터넷 차단·인쇄 QR 검증이 남아 있다. 이 확인 전에는 전시 준비 완료로 선언하거나 관련 이슈를 닫지 않는다.
