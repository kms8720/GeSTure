# 제주 휴대폰 전시 네트워크 준비와 검증

서버와 관객 휴대폰이 서로 통신할 수 있는 LAN이 필요하다. 인터넷은 필수 조건이 아니다.
기존 Wi-Fi도 기기 간 통신을 허용하면 사용할 수 있다. 노트북은 유선, 휴대폰은 Wi-Fi여도
동일 공유기의 LAN에 속하면 된다. 휴대폰에서 localhost로 노트북에 접속할 수는 없다.

## 구성

1. 공유기의 관객 SSID에서 AP isolation / client isolation / 게스트 기기 격리가 켜져 있는지 확인한다.
   관객망의 통신 제한을 바꾸는 것은 주최측과 협의하고, 작품용 망을 쓰는 경우에만 해당 설정을 조정한다.
2. 서버 노트북의 LAN IP를 확인하고 공유기의 DHCP 주소 예약에 등록한다.
3. `.env`의 PUBLIC_ORIGIN에 해당 주소와 서버 포트를 입력한다. WIFI_SSID / WIFI_PASSWORD도 입력한다.
   IP 변경 시 QR을 다시 인쇄해야 한다. 현재 테스트 노트북의 IP를 현장 고정 IP로 간주하지 않는다.
4. `npm run setup`, `npm run build`, `npm start`로 실행한다.
5. `npm run check:network -- http://서버IP:3002`를 수행한다.
6. `/join/qr`에서 인쇄한다. Wi-Fi QR과 참여 QR을 각각 스캔해 실제 연결 여부를 확인한다.
7. macOS 방화벽이 연결을 막는 경우 Node의 인바운드 연결 허용 여부를 확인한다.
   방화벽 전체를 끄지 않는다.

개발 검증은 서버 프로세스와 독립된 소켓 8개로 수행한다. 이는 실제 휴대폰 8대의 검증을 대신하지 않는다.
브라우저에서 `/check`를 열면 해당 기기의 HTTP 응답과 실시간 연결 여부를 확인할 수 있다.
`/check`는 손가락 자리를 점유하지 않는다.

## 실패 시 확인 순서

1. 노트북에서 `/health`와 `/join`이 열리는지 확인한다.
2. 휴대폰이 노트북과 통신 가능한 SSID에 있는지 확인한다. 인터넷이 없다는 안내 뒤에도 그 Wi-Fi를 유지한다.
3. 노트북 IP와 PUBLIC_ORIGIN, 인쇄 주소가 일치하는지 확인한다.
4. 휴대폰의 `/check`에서 HTTP와 실시간 조종 연결 중 어느 쪽이 실패하는지 구분한다.
5. 공유기의 게스트망 격리, 방화벽과 VPN 경로를 확인한다. 네트워크 설정 변경은 담당자와 협의한다.

## 전시 완료 판정

코드 테스트가 통과해도 위 실기 항목과 실제 장비 연속 리허설이 남아 있으면
현장 네트워크가 준비됐다고 표시하지 않는다. 전시용 SSID·고정 IP 확정과
iPhone·Android 실기 결과가 모두 확보된 뒤 완료 상태로 갱신한다.
30분 순환 검사는 사전 점검이다. 최종 전시 판정에는 실제 휴대폰 5대와 대기 3대,
손·단어 디스플레이를 함께 사용한 8시간 연속 리허설이 필요하다.
이 과정에서 단어 반복 완주, 관객 교체, 화면 잠금·복귀, 서버·공유기 재시작과
LLM 중단 후 대체 생성을 확인한다. 소프트웨어 소켓 테스트로 이 기준을 대체하지 않는다.
