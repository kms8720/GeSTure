# GeSTure 제주 전시

ACCxGMAP 본 전시와 별개로 진행하는 **제주 전시 전용 서브프로젝트**다.
기존 `virtual-hand-rigged-final/`(ACC용)은 건드리지 않는다.

## ACC 버전과 무엇이 다른가

| | ACC (`virtual-hand-rigged-final/`) | 제주 (여기) |
| --- | --- | --- |
| 자모 인식 | 손가락 5비트 → 자모 31개 순서 배정 | 실측 지화 포즈 17개 클래스 최근접 |
| 자모 확정 | 포즈 1개 = 자모 1개 | 포즈 1개 = **자모 후보 여러 개** |
| 조종기 | 관객 휴대폰, 손가락별 QR | **관객 휴대폰, 손가락별 QR 5개 + 해당 손가락 대기** |
| 화면 | display / recognition / links | **손 화면 + 단어 화면 분리** + QR 안내 + monitor |
| LLM 실패 시 | `안녕` 하드코딩 | **단어장 기반 결정론적 대체 경로** |
| LLM 타임아웃 | 없음 (무한 대기 가능) | 20초 + 부팅 시 예열 |
| 손가락 벌림 | 없음 | **굽힘에 연동** — 펴면 퍼지고 접으면 오므라듦 |
| 포트 | 3001 | 3002 |

핵심 차이는 두 번째 줄이다. 이 손은 손목을 움직이지 못해서 `ㅏ`/`ㅓ`, `ㅗ`/`ㅜ`처럼
손 방향으로만 갈리는 자모를 구분할 수 없다. 그 모호함을 없애는 대신 그대로 남겨
LLM에 넘긴다. 근거와 도출 과정은 [docs/pose-derivation.md](docs/pose-derivation.md)에 있다.

## 전시장 구성

디스플레이 2대와 손가락별 QR 5개를 담은 안내물로 구성한다. 손과 단어를 분리한 이유는 손을 최대한 크게 보여주기 위해서다.
ACC 전시에서도 단어는 프로젝터나 별도 화면으로 손과 분리할 예정이라 구성을 맞췄다.

```
   ┌──────────┐        ┌─────────────────────┐
   │          │        │                     │
   │   손만   │        │    자모 후보         │
   │  (세로)  │        │    슬롯 진행         │
   │          │        │    만들어진 단어      │
   │          │        │                     │
   └──────────┘        └─────────────────────┘
  /display/hand           /display/word

  엄지·검지·중지·약지·소지 QR → /join?finger=thumb 등
    → 선택한 손가락 배정, 사용 중이면 그 손가락의 차례 대기

  운영자용(관객에게 안 보임): /monitor
```

손 화면에는 관객에게 보이는 요소가 하나도 없다. 서버가 끊겼을 때만 배너가 뜬다.
세로 디스플레이를 전제로 카메라를 잡아두었다(`VirtualHand`의 `framing="portrait"`).

## 실행

```sh
cd jeju-exhibition
npm install
npm run setup
# .env의 PUBLIC_ORIGIN / WIFI_SSID / WIFI_PASSWORD를 현장 정보로 설정
npm run build
npm start
```

부팅 로그에 각 화면 주소가 LAN IP로 찍힌다. `/join/qr`은 관객 안내용 QR 화면이다.

```
손 화면 (세로)  http://<IP>:3002/display/hand
단어 화면       http://<IP>:3002/display/word
관객 참여        http://<IP>:3002/join
QR 안내 화면     http://<IP>:3002/join/qr
운영 모니터     http://<IP>:3002/monitor
휴대폰 연결 점검 http://<IP>:3002/check
```

개발 중에는:

```sh
npm run dev        # 서버 3002 + vite 5174
npm run typecheck  # 클라이언트 + 서버
npx tsx server/smoke.ts   # 인식기/단어 생성 파이프라인 점검
```

## 동작

```
관객이 손가락별 QR로 접속 → 선택한 손가락을 독점 배정
  → 사용 중인 손가락은 해당 손가락 대기, 퇴장 또는 연결 만료 시 자동 승계
  → 각자 휴대폰에서 손가락 굽힘 조절
  → 굽힘 5개 값
  → 17개 지화 포즈 클래스 중 최근접 (도달 확률 균등화 bias 적용)
  → 100ms 주기 평가, 400ms 유지되면 추가 입력 없이 슬롯에 기록 (자모 후보 집합 그대로)
  → 슬롯 6개가 모이면 단어 생성
      Ollama가 후보 조합에서 뜻이 통하는 단어를 고름 (기본 전시 모드는 단어장 안으로 제한)
      실패하면 단어장에서 후보 자모로 가장 잘 설명되는 단어
  → /display/word 에 표시. 손은 /display/hand 에서 계속 움직인다
```

같은 포즈 클래스는 한 단어 안에서 한 번만 기록된다.
다섯 손가락을 모두 펴면(85 이상) rest로 보고 아무것도 기록하지 않는다.
단어 완성·초기화·자리 반환 뒤에는 새로운 실제 조작이 있어야 다음 기록을 시작한다.
현재 손잡이 위치를 다시 조작하는 것도 실제 입력으로 인정한다.
생성 중 입력은 손을 움직이지만 다음 단어에 자동 기록하지 않는다.
마지막 관객이 연결을 끊으면 인식 기록을 잠시 멈춘다. 손가락 값은 기존 15초 유예 정책을 따른다.
상태가 달라졌을 때만 브로드캐스트하며 입력 드래그 빈도와 별개로 최대 10Hz로 갱신한다.

관객 조종 화면은 배정된 손가락 이름과 세로 드래그 조종기 하나로 구성한다.
위로 밀면 펴지고 아래로 내리면 접힌다. 숫자·단계 버튼·참여 인원은 표시하지 않는다.
드래그는 손잡이 주변의 넓은 영역에서도 시작할 수 있고, 서버 응답 전에 화면이 즉시 따라온다.
대기·연결 오류·운영자 반환 시에는 해당 안내 화면을 표시한다.
참여를 마치려면 휴대폰의 조종 화면을 닫는다. 서버는 15초 재접속 유예 뒤 자리를 반환한다.
같은 휴대폰에서 다른 손가락 QR을 스캔하면 기존 손가락을 반환하고 새 손가락으로 이동한다.
새 손가락이 사용 중이면 다른 빈 손가락으로 바꾸지 않고 해당 손가락을 기다린다.
기존 `/join` 주소는 빈 손가락 자동 배정을 유지하지만 안내판은 손가락별 주소를 사용한다.

## 운영자 키와 결과 제어

`npm run setup`은 `.env`에 무작위 운영자 키를 생성한다. 기존 키와 설정은 재실행해도 유지한다.
`npm start`는 `.env`를 읽는다. Node.js 22.18 이상을 사용한다.
`/monitor`에서 `.env`의 `OPERATOR_TOKEN` 값을 입력하면 초기화, 강제 단어 생성, 자리 반환,
`지금 단어 내리기`를 사용할 수 있다. 키는 현재 화면의 메모리에만 두므로 새로고침하면 다시 입력한다.

모든 POST API는 `Authorization: Bearer <운영자 키>`를 요구한다. 키가 없으면 503, 틀리면 401이다.
관객 QR과 URL에는 운영자 키를 넣지 않는다. 관객의 소켓 조종은 별도 참여 토큰으로 배정한 손가락만 허용한다.
한 소켓의 다른 토큰 재입장은 거부하며, 같은 토큰의 새 탭은 기존 탭의 조종 권한을 넘겨받는다.

`지금 단어 내리기`는 현재 단어를 화면과 메모리 기록에서 제거하고 진행 중 결과도 취소한다.
초기화·결과 내리기 뒤 늦게 돌아온 생성 응답은 화면에 반영하지 않는다.

## 휴대폰 접속과 QR 안내판

같은 Wi-Fi에 연결된 노트북과 휴대폰으로 테스트할 수 있다. 공유기가 기기 간 통신을 허용해야 한다.
휴대폰의 `localhost`는 휴대폰 자신이므로 노트북의 LAN IP로 접속한다.
전시에서는 공유기의 DHCP 주소 예약으로 서버 IP를 고정하고 아래 항목을 `.env`에 입력한다.

```dotenv
# 예시 주소이며 실제 서버 IP로 변경
PUBLIC_ORIGIN=http://192.168.50.10:3002
WIFI_SSID=작품용-WiFi
WIFI_PASSWORD=관객용-비밀번호
```

`/join/qr`에는 Wi-Fi 이름·비밀번호와 엄지·검지·중지·약지·소지 QR 5개가 표시된다.
각 QR에는 `/join?finger=thumb|index|middle|ring|pinky` 중 하나의 주소가 들어간다.
화면의 참여 가능·사용 중 표시는 실시간으로 갱신된다. 인쇄물에는 이 상태 표시를 넣지 않는다.
고정 참여 주소와 Wi-Fi 이름이 설정되면 안내판 인쇄 버튼을 사용할 수 있다.
비밀번호는 관객용 전용 Wi-Fi 정보이며 운영자 키와 반드시 다르게 둔다.
여러 LAN 주소가 감지되면 첫 번째 주소를 임의로 QR에 쓰지 않는다.
`PUBLIC_ORIGIN`에 localhost, 계정 정보, 경로, 쿼리를 넣으면 서버가 시작되지 않는다.

```sh
npm run check:network -- http://실제서버IP:3002
```

이 명령은 화면과 API, 실시간 소켓 상태 수신, 안내 설정과 검사 주소 일치를 확인한다.
Wi-Fi 안내가 없거나 localhost로 검사하면 성공으로 처리하지 않는다.
명령의 성공만으로 휴대폰 실기·공유기 설정이 검증된 것은 아니다.
현장 절차와 남은 실기 항목은 [docs/network-setup.md](docs/network-setup.md)를 따른다.

## 개발 중 주의 — 노트북이 뜨거워진다

전시 장비에서는 맞는 설정이 개발용 노트북에서는 부담이 된다. 두 가지다.

### 1. 손 화면은 열어두는 것만으로 계속 GPU를 쓴다

`/display/hand`는 WebGL로 로봇손을 쉬지 않고 그린다. 그림자 맵이 2048px이고
프레임 제한이 없어서, 탭이 배경에 있어도 계속 돌아간다. 실측한 값이다.

```
Chrome Helper            26.9%
Chrome Helper (Renderer) 17.1%
```

확인하지 않을 때는 탭을 닫거나 `about:blank`로 돌려둔다.
LLM 응답이 느려지는 것도 같은 원인이다. 이 화면을 띄운 채로 재면 생성 속도가
초당 9토큰까지 떨어진다(보통 30~50토큰/초).

### 2. `OLLAMA_KEEP_ALIVE` 기본값은 전시용이다

기본값 `8h`는 모델을 8시간 동안 메모리에 붙잡아둔다. 전시장에서는 이게 맞다.
관객이 콜드 로드를 기다리지 않아야 하기 때문이다. 대신 7B 모델이 5GB 남짓을 계속 문다.

개발 중에는 짧게 잡는다.

```sh
OLLAMA_KEEP_ALIVE=5m npm start
```

이미 올라간 모델을 지금 내리려면:

```sh
curl -s http://127.0.0.1:11434/api/chat \
  -d '{"model":"qwen2.5:7b-instruct","messages":[],"keep_alive":0}'
curl -s http://127.0.0.1:11434/api/ps    # 비어 있으면 내려간 것
```

전시 당일에는 기본값을 그대로 쓴다.

## 환경변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | 3002 | |
| `SLOTS_PER_WORD` | 6 | 단어 하나에 필요한 손 모양 개수 |
| `POSE_HOLD_MS` | 400 | 이 시간 유지해야 슬롯에 기록 |
| `PUBLIC_ORIGIN` | 자동 감지 | 인쇄 QR에 사용할 고정 서버 origin |
| `WIFI_SSID` / `WIFI_PASSWORD` | 없음 | 관객용 Wi-Fi 이름·비밀번호 안내 |
| `OPERATOR_TOKEN` | 없음 | 미설정 시 변경 API 잠김, setup으로 생성 |
| `EXHIBITION_STRICT` | 1 | 전시 출력은 검토된 단어장으로 제한 |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | |
| `OLLAMA_MODEL` | `qwen2.5:7b-instruct` | |
| `OLLAMA_TIMEOUT_MS` | 20000 | 넘기면 단어장으로 대체 |
| `WORD_DEADLINE_MS` | 20000 | 생성과 추가 검증을 합친 전체 시간 상한 |
| `OLLAMA_KEEP_ALIVE` | `8h` | 전시 중 모델 언로드 방지 |

기본 전시 모드는 목록 밖 결과를 추가 LLM 호출 없이 단어장으로 대체한다.
형식 오류, 금칙어, 연결 실패, 시간 초과도 같은 대체 경로를 사용한다.
`EXHIBITION_STRICT=0`은 개발 실험용으로만 사용하며, 목록 밖 단어의 추가 검증도 전체 시간 상한을 공유한다.

## GLB 파일

`public/models/robot_hand_rig.glb`는 ACC 폴더의 68MB 파일을 가리키는 심볼릭 링크다.
복제하면 저장소가 68MB 더 커진다. 나중에 두 프로젝트를 완전히 분리한다면
그때 실제 파일로 바꾸고, 이왕이면 Git LFS로 옮기는 것이 좋다.

## 실측으로 확인한 것

- 17개 클래스 전부 자기 대표 굽힘값으로 자기 클래스에 인식된다
- 도달 확률 편차 20.8배 → 1.0배 (관객이 슬라이더를 끝까지 미는 경향에서도 2.2배)
- Ollama 예열 전 첫 호출 12초 초과 → `keep_alive` + 부팅 시 예열로 해결
- `[ㅅ][ㅏㅓ][ㄹ][ㅏㅗ][ㅇ][ㅁㄴ]` → `사랑`
- `[ㄷㅅㅈㅑㅛㅠ][ㄱㄴㅏㅗㅜㅡ][ㄹㅌ][ㅇ][ㅁ][ㅣ]` → `인사`
- Ollama를 끄면 같은 입력이 단어장 경로로 `이름`을 낸다 (19ms)

### LLM 지연 — 프롬프트와 출력을 줄인 이유

전시 화면이 렌더링 중인 같은 기계에서 측정한 값이다.

| | 입력 | 출력 | 총 |
| --- | ---: | ---: | ---: |
| 처음 (후보 12개 + note/candidates까지 LLM에게) | 625토큰 / 2.6~4.0s | 67토큰 / 7.6s | **15.3s** |
| 지금 (후보 6개, correctedWord와 chosenJamo만) | 약 300토큰 | 약 20토큰 | **2.7~3.2s** |

생성 속도가 초당 9토큰밖에 안 나왔다. Apple Silicon에서 7B 모델이면 보통 30~50토큰/초다.
WebGL로 로봇손을 계속 그리는 화면이 같은 GPU를 쓰기 때문이다.

그래서 **출력 토큰 하나가 비싸다**. 화면에 나가지도 않는 `note`와 `candidates`를 LLM에게
시키는 것만으로 5초가 더 들었다. 둘 다 서버에서 만든다.

전시에서는 화면 기계와 LLM 기계를 분리할 예정이라 이 경합은 사라진다.
분리하면 `OLLAMA_URL`을 LLM 기계 주소로 잡으면 된다.

## 손가락 좌우 벌림은 실측이다

손 개폐 영상 63초를 따로 찍어 측정했다. `reference_samples.jsonl`로는 구할 수 없었다.
그건 31개 정적 지화라 손을 쥐고 펴는 동작 자체가 없고, 굽힘-벌림 상관이 전체 -0.04였다.

```
1620x1080, 30fps -> 10fps 프레임 630장 -> MediaPipe 검출 620장 (98%)
```

| | 검지 | 중지 | 약지 | 소지 | 폭 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 펴짐 (n=183) | -6.6° | -1.0° | +0.9° | +6.7° | **13.3°** |
| 접힘 (n=25) | -2.4° | +1.2° | +1.9° | -0.7° | **4.3°** |

부채꼴 폭이 13.3도에서 4.3도로 줄어든다. 손을 쥐면 손가락이 모인다.
도출 과정은 [docs/pose-derivation.md](docs/pose-derivation.md)에 있다.

다시 측정하려면:

```sh
ffmpeg -i 영상.mov -vf "fps=10,scale=1080:-1" -q:v 2 frames/f%05d.jpg
.venv/bin/python jeju-exhibition/scripts/analyze_hand_video.py frames/
```
