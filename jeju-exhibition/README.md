# GeSTure 제주 전시

ACCxGMAP 본 전시와 별개로 진행하는 **제주 전시 전용 서브프로젝트**다.
기존 `virtual-hand-rigged-final/`(ACC용)은 건드리지 않는다.

## ACC 버전과 무엇이 다른가

| | ACC (`virtual-hand-rigged-final/`) | 제주 (여기) |
| --- | --- | --- |
| 자모 인식 | 손가락 5비트 → 자모 31개 순서 배정 | 실측 지화 포즈 17개 클래스 최근접 |
| 자모 확정 | 포즈 1개 = 자모 1개 | 포즈 1개 = **자모 후보 여러 개** |
| 조종기 | 관객 휴대폰, QR 접속 | **전용 디스플레이 5대** 고정 |
| 화면 | display / recognition / links | **손 화면 + 단어 화면 분리** + 조종기 5대 + monitor |
| LLM 실패 시 | `안녕` 하드코딩 | **단어장 기반 결정론적 대체 경로** |
| LLM 타임아웃 | 없음 (무한 대기 가능) | 20초 + 부팅 시 예열 |
| 손가락 벌림 | 없음 | **굽힘에 연동** — 펴면 퍼지고 접으면 오므라듦 |
| 포트 | 3001 | 3002 |

핵심 차이는 두 번째 줄이다. 이 손은 손목을 움직이지 못해서 `ㅏ`/`ㅓ`, `ㅗ`/`ㅜ`처럼
손 방향으로만 갈리는 자모를 구분할 수 없다. 그 모호함을 없애는 대신 그대로 남겨
LLM에 넘긴다. 근거와 도출 과정은 [docs/pose-derivation.md](docs/pose-derivation.md)에 있다.

## 전시장 구성

디스플레이 7대다. 손과 단어를 분리한 이유는 손을 최대한 크게 보여주기 위해서다.
ACC 전시에서도 단어는 프로젝터나 별도 화면으로 손과 분리할 예정이라 구성을 맞췄다.

```
   ┌──────────┐        ┌─────────────────────┐
   │          │        │                     │
   │   손만   │        │    자모 후보         │
   │  (세로)  │        │    슬롯 진행         │
   │          │        │    만들어진 단어      │
   │          │        │                     │
   └──────────┘        └─────────────────────┘
  /display/hand           /display/word

  ┌────┐  ┌────┐  ┌────┐  ┌────┐  ┌────┐
  │ 1  │  │ 2  │  │ 3  │  │ 4  │  │ 5  │
  │엄지 │  │검지 │  │중지 │  │약지 │  │소지 │
  └────┘  └────┘  └────┘  └────┘  └────┘
   /control/thumb  index  middle  ring  pinky

  운영자용(관객에게 안 보임): /monitor
```

손 화면에는 관객에게 보이는 요소가 하나도 없다. 서버가 끊겼을 때만 배너가 뜬다.
세로 디스플레이를 전제로 카메라를 잡아두었다(`VirtualHand`의 `framing="portrait"`).

## 실행

협업자 PC에는 Node.js 22.12 이상과 npm, Ollama가 필요하다. Ollama를 실행한 상태에서 아래 명령으로 모델을 준비한다. 기본 연결 주소는 `http://127.0.0.1:11434`다.

```sh
ollama pull qwen2.5:7b-instruct
```

저장소 루트에서 설치·빌드·실행한다. `npm ci`는 커밋된 lockfile의 의존성을 설치한다. 앱용 손 모델 GLB와 리그 JSON은 저장소에 포함되어 있으며, 일반 실행에는 Blender가 필요 없다.

```sh
cd jeju-exhibition
npm ci
npm run build
npm start
```

실행 후 **[전시 화면 모아보기](http://localhost:3002/exhibition)** 를 열면 손·단어·조종기 5개와 추가 워드클라우드 화면을 한 페이지에서 확인할 수 있다. 기본 주소 `/`도 이 페이지로 연결된다.
조종기 미리보기를 직접 조작할 수 있으며, ‘크게 열기’는 해당 전시 화면만 새 탭에 연다.
실제 전시장에서는 각 디스플레이에 아래의 개별 주소를 띄운다. 다른 PC에서는 `localhost` 대신 서버 PC의 LAN IP를 사용한다.
운영 모니터는 모아보기에서 제외했다.

추가 전시 화면 **[워드클라우드](http://localhost:3002/word-cloud/)** 는 제공된 `WordCloud.html`을 가져온 것이다.
10초마다 단어가 모였다 흩어지는 원본 연출을 유지하며, 실제 손가락 조종으로 생성된 단어를 실시간으로 받는다.
`public/word-cloud/exhibition.css`에서 배경·색상·글꼴·장식만 GeSTure 전시 디자인에 맞췄다.
샘플 단어나 준비된 문장은 사용하지 않는다. 서로 다른 단어 2개부터 Ollama가 문장을 만들고, 이후에는 최근 고유 단어 최대 3개로 새 문장을 만든다.
입력 단어를 모두 포함하는 한글 한 문장인지 검사하고, 잘못된 모델 출력은 한 번 재시도한다. 실패하면 이전 문장을 유지하며 다음 단어 입력 때 다시 시도한다.
새 단어가 생성 도중 도착하면 이전 결과를 표시하지 않고 대기 중인 입력을 최신 묶음 하나로 합쳐 다시 생성한다. 모아보기에는 단어 수·문장 생성 상태·최신 문장도 표시한다.
워드클라우드는 서버 실행 중 고유 단어 50개, 문장 8개까지 보관한다. 새로고침·다른 화면 접속 시 현재 상태를 다시 받으며 서버 재시작 시 새 전시 세션으로 시작한다.
회귀검사: `npm run test:word-cloud`.

부팅 로그에 각 화면 주소가 LAN IP로 찍힌다. 조종기 디스플레이는 그 주소를 각각 띄워두면 된다.
앱은 신뢰하는 로컬/LAN 전시 환경용이며 별도 사용자 인증이 없다. 비공개 GitHub 저장소 링크는 코드 공유용이고, 앱을 인터넷에 공개 배포하는 링크가 아니다.

```
손 화면 (세로)  http://<IP>:3002/display/hand
단어 화면       http://<IP>:3002/display/word
조종기 1~5      http://<IP>:3002/control/thumb ... /pinky
운영 모니터     http://<IP>:3002/monitor
```

개발 중에는:

```sh
npm run dev        # 서버 3002 + vite 5174
npm run typecheck  # 클라이언트 + 서버
npm run test:word-correction  # 입력 자모 반영·보완 개수
npm run test:word-cloud       # 문장 검증·생성 대기열·클라우드 상태
npx tsx server/smoke.ts   # 인식기/단어 생성 파이프라인 점검
```

## 동작

```
관객 5명이 조종기 5대로 손가락 굽힘 조절
  → 굽힘 5개 값
  → 17개 지화 포즈 클래스 중 최근접 (도달 확률 균등화 bias 적용)
  → 400ms 유지되면 슬롯에 기록 (자모 후보 집합 그대로)
  → 슬롯 6개가 모이면 단어 생성
      Ollama가 후보 조합에서 뜻이 통하는 단어를 고름
      실패하면 단어장에서 후보 자모로 가장 잘 설명되는 단어
  → /display/word 에 표시. 손은 /display/hand 에서 계속 움직인다
```

같은 포즈 클래스는 한 단어 안에서 한 번만 기록된다.
다섯 손가락을 모두 펴면(85 이상) rest로 보고 아무것도 기록하지 않는다.

모아보기와 운영 모니터에는 결과 단어의 **입력 자모 반영 수 / AI 보완 수**를 구분해 표시한다.
결과 단어를 기본 자모로 분해하고, 입력 슬롯 하나당 자모 하나만 대응시켜 설명할 수 있는 최대 개수를 센다.
같은 자모가 반복되면 각각 별개로 세며, 나머지는 보완 수다. Ollama 실패 시에는 **단어장 보완**으로 표시한다.
예를 들어 `[ㅂ][ㅒ][ㅐㅚㅟㅢ][ㅣ][ㅓ][ㅎ]`에서 ‘행복’이 나오면 입력 3개(ㅎ·ㅐ·ㅂ), AI 보완 3개(ㅇ·ㅗ·ㄱ)다.
계산 회귀검사는 `npm run test:word-correction`으로 실행한다.

## 개발 중 주의 — 노트북이 뜨거워진다

전시 장비에서는 맞는 설정이 개발용 노트북에서는 부담이 된다. 두 가지다.

### 1. 손 화면은 움직일 때 GPU를 쓴다

새 전시 렌더러는 `frameloop="demand"`를 사용한다. 입력이 바뀌면 관절을 부드럽게
움직이고, 목표 자세에 도달하면 연속 렌더링을 멈춘다. 그림자 맵은 1024px,
화면 픽셀 비율은 최대 1.5다. 아래는 변경 전 연속 렌더러에서 측정한 값이다.

```
Chrome Helper            26.9%
Chrome Helper (Renderer) 17.1%
```

확인하지 않을 때는 탭을 닫거나 `about:blank`로 돌려둔다.
LLM 응답이 느려지는 것도 같은 원인이다. 이 화면을 띄운 채로 재면 생성 속도가
초당 9토큰까지 떨어진다(보통 30~50토큰/초).

### 2. `OLLAMA_KEEP_ALIVE` 기본값은 전시용이다

기본값 `8h`는 모델을 8시간 동안 메모리에 붙잡아둔다. 전시장에서는 이게 맞다.
관객이 콜드 로드를 기다리지 않아야 하기 때문이다. 대신 7B 모델이 5GB 남짓을 계속 문다.

개발 중에는 짧게 잡는다.

```sh
OLLAMA_KEEP_ALIVE=5m npm start
```

이미 올라간 모델을 지금 내리려면:

```sh
curl -s http://127.0.0.1:11434/api/chat \
  -d '{"model":"qwen2.5:7b-instruct","messages":[],"keep_alive":0}'
curl -s http://127.0.0.1:11434/api/ps    # 비어 있으면 내려간 것
```

전시 당일에는 기본값을 그대로 쓴다.

## GLB 파일

제주 화면은 `public/models/hand_exhibition.glb`와 `hand_exhibition.rig.json`을 사용한다.
Meshy 원본 `hand color.glb`의 손바닥과 네 손가락에 기존 ACC 모델의 검지만 원형 그대로 결합한 리그이며,
각 관절의 로컬 회전축과 최대 굽힘각은 JSON에 기록되어 있다. 조종값은 기존과 같이
100=펴짐, 0=접힘이다. 인식 알고리즘은 모델 메시 대신 이 다섯 값을 사용하므로 바뀌지 않는다.

재생성 스크립트는 `scripts/build_exhibition_hand.py`, 구조 검증은
`scripts/validate_hand_glb.py`다. Blender 편집용 결과와 자세 검수 이미지는
로컬 `../data/model-work/`에 저장된다. 원본 GLB는 수정하지 않는다.

기존 ACC의 `robot_hand_rig.glb`는 생성 시 검지의 원본으로만 읽고 앱은 결합된 GLB 하나를 불러온다.
제주 폴더의 심볼릭 링크 대신 ACC 폴더의 실제 파일을 사용한다. 출처와 재생성·검증 절차는 [손 모델 문서](docs/hand-model.md)에 있다.

## 전시 화면 디자인

손은 먹색 공간과 따뜻한 측면 조명으로, 단어는 아이보리 명조체와 넓은 여백으로 보여준다.
관객 화면에는 여섯 개 진행점과 현재 자모 후보만 작게 남기며 모델·처리 시간·상태 정보는
`/monitor`에서 확인한다. 조종기는 동일한 색상과 서체, 손가락별 번호를 사용한다.
글꼴은 기기에 설치된 명조체/고딕체를 사용하므로 전시장 기기에서도 최종 외형을 확인해야 한다.

## 실측으로 확인한 것

- 17개 클래스 전부 자기 대표 굽힘값으로 자기 클래스에 인식된다
- 도달 확률 편차 20.8배 → 1.0배 (관객이 슬라이더를 끝까지 미는 경향에서도 2.2배)
- Ollama 예열 전 첫 호출 12초 초과 → `keep_alive` + 부팅 시 예열로 해결
- `[ㅅ][ㅏㅓ][ㄹ][ㅏㅗ][ㅇ][ㅁㄴ]` → `사랑`
- `[ㄷㅅㅈㅑㅛㅠ][ㄱㄴㅏㅗㅜㅡ][ㄹㅌ][ㅇ][ㅁ][ㅣ]` → `인사`
- Ollama를 끄면 같은 입력이 단어장 경로로 `이름`을 낸다 (19ms)

### LLM 지연 — 프롬프트와 출력을 줄인 이유

전시 화면이 렌더링 중인 같은 기계에서 측정한 값이다.

| | 입력 | 출력 | 총 |
| --- | ---: | ---: | ---: |
| 처음 (후보 12개 + note/candidates까지 LLM에게) | 625토큰 / 2.6~4.0s | 67토큰 / 7.6s | **15.3s** |
| 지금 (후보 6개, correctedWord와 chosenJamo만) | 약 300토큰 | 약 20토큰 | **2.7~3.2s** |

생성 속도가 초당 9토큰밖에 안 나왔다. Apple Silicon에서 7B 모델이면 보통 30~50토큰/초다.
WebGL로 로봇손을 계속 그리는 화면이 같은 GPU를 쓰기 때문이다.

그래서 **출력 토큰 하나가 비싸다**. 화면에 나가지도 않는 `note`와 `candidates`를 LLM에게
시키는 것만으로 5초가 더 들었다. 둘 다 서버에서 만든다.

전시에서는 화면 기계와 LLM 기계를 분리할 예정이라 이 경합은 사라진다.
분리하면 `OLLAMA_URL`을 LLM 기계 주소로 잡으면 된다.

## 남은 일

0. **`ㅁ`, `ㅔ`, `ㅕ` 다시 촬영.** 표준 지화 조사와 대조한 결과 31개 중 이 셋만
   손 모양 패턴이 어긋난다(상관 -0.48 / 0.25 / 0.27, 나머지는 평균 0.9 이상).
   동시에 이 셋은 같은 자모 안에서의 촬영 산포도 가장 큰 축에 속한다.
   다시 찍고 `scripts/analyze_poses.py`를 돌리면 클래스 구성이 개선된다.
   자세한 내용은 [docs/pose-derivation.md](docs/pose-derivation.md).
1. **방향 프리셋 좌표계 보정 (선택).** 손은 현재 항상 정면을 향한다
   (`USE_POSE_ORIENTATION = false`). 실측 방향값이 MediaPipe 카메라 좌표계 기준이라
   three.js 축과 대응이 맞지 않아 꺼둔 것이다. 켜려면 [docs/pose-derivation.md](docs/pose-derivation.md)의
   보정 절차를 따른다. 켜지 않아도 전시는 성립한다.
2. **디스플레이 실기 확인.** 조종기 화면 해상도와 방향(세로/가로)을 모르는 상태로 만들었다.
   세로 기준으로 짰고 가로에서도 깨지진 않지만 실기에서 봐야 한다.
3. **단어장 확장.** 지금 150개 남짓이다. 전시 시간이 길면 반복이 눈에 띌 수 있다.
4. **전시 로그.** 만들어진 단어와 그때의 슬롯을 파일로 남기는 기능이 아직 없다.
5. **전시장 디자인 검수.** 손·단어·조종기·워드클라우드 디자인은 적용했다. 실제 투사 크기와 조명에서 글자 가독성, 대비, 관절 연결부를 확인해야 한다.

## 손가락 좌우 벌림은 실측이다

손 개폐 영상 63초를 따로 찍어 측정했다. `reference_samples.jsonl`로는 구할 수 없었다.
그건 31개 정적 지화라 손을 쥐고 펴는 동작 자체가 없고, 굽힘-벌림 상관이 전체 -0.04였다.

```
1620x1080, 30fps -> 10fps 프레임 630장 -> MediaPipe 검출 620장 (98%)
```

| | 검지 | 중지 | 약지 | 소지 | 폭 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 펴짐 (n=183) | -6.6° | -1.0° | +0.9° | +6.7° | **13.3°** |
| 접힘 (n=25) | -2.4° | +1.2° | +1.9° | -0.7° | **4.3°** |

부채꼴 폭이 13.3도에서 4.3도로 줄어든다. 손을 쥐면 손가락이 모인다.
도출 과정은 [docs/pose-derivation.md](docs/pose-derivation.md)에 있다.

다시 측정하려면:

```sh
ffmpeg -i 영상.mov -vf "fps=10,scale=1080:-1" -q:v 2 frames/f%05d.jpg
.venv/bin/python jeju-exhibition/scripts/analyze_hand_video.py frames/
```
